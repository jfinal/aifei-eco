# aifei-cache 开发约束

本文件适用于整个仓库，供开发代理和项目贡献者使用。

## 开发前提

- 开始设计或修改代码前，必须先阅读 `docs/design.md`。
- `docs/design.md` 是项目设计目标、约束和决策的事实来源。
- 如果需求与现有设计文档冲突，应先明确并更新设计决策，再修改代码。

## 硬性约束

- 保持 `Cache` 公共 API 极简、实现无关。
- 用户业务代码只依赖 `Cache` 接口，通过 aifei `@Inject` 注入具体实现。
- 公共 API 不得暴露 Caffeine、Jedis、Fury 或其他具体实现的类型。
- `CaffeineCache` 与 `RedisCache` 必须遵循相同的接口契约和公共行为。
- 项目代码、依赖和 API 必须兼容 Java 8。
- 未经设计决策，不得自行确定空值、过期时间、序列化、异常处理或 key 规则。

## 文档维护

- 面向使用者的定位、场景和用法维护在 `README.md`。
- 设计目标、行为契约、关键决策和待决策事项维护在 `docs/design.md`。
- 新增或改变公共行为时，应同步更新设计文档和测试。
